# SpawnWP 0.5.25

Three fixes for the same underlying report: a site running MailerPress returned
frequent 502s reading "WordPress environment is not running" (GitHub issue #13).
None of them are specific to that plugin — they affect any site doing similar work.

## The edge proxy no longer cuts off long requests

The nginx location in front of every WordPress site had no explicit
`proxy_read_timeout`/`proxy_send_timeout`, so it used nginx's compiled-in 60-second
default. PHP itself is allowed to run for 120 seconds, and the container's own internal
proxy allows 300 — so a request that ran past 60 seconds, WordPress still working
underneath, got killed by the outer proxy and shown to the visitor as a dead
environment.

The outer proxy now allows 300 seconds too, matching the inner one. Existing
installations get this through the update's migration, which patches every site
location already in the live nginx config, not just newly created ones.

## WP-Cron runs again

Every spawned site force-disabled WP-Cron with no substitute trigger. Concretely:
nothing was wrong with the constant itself, but nothing ever replaced what it turned
off, so any plugin relying on scheduled events — a mail queue processed in the
background, scheduled posts, cleanup tasks — silently never ran on any site except the
primary development one, which happened to have a manual cron entry from an earlier
setup.

New sites now get WordPress's ordinary pseudo-cron behaviour back: due events run on
the next page visit, exactly as on any hosting that hasn't touched `DISABLE_WP_CRON`.
The update's migration clears the constant on every existing site's `wp-config.php`.

## Mailpit captures mail on every blueprint

The hook that pointed outgoing mail at a site's Mailpit only installed alongside the
Development blueprint's debug toolkit — so Clean and Demo sites had the `SMTP_HOST`/
`SMTP_PORT` constants sitting in `wp-config.php` with nothing acting on them, and
`wp_mail()` silently went nowhere instead of landing in Mailpit.

Mail capture is now installed independently of the debug toolkit, on every site
regardless of blueprint. The update's migration adds it to existing sites too.
