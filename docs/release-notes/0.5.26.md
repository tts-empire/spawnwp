# SpawnWP 0.5.26

A follow-up to 0.5.25, whose update failed on the migration step.

## The update to 0.5.25 could fail

0.5.25 added a migration that installs `mail-capture.php` on every existing site. The
migration located its own source file assuming the release payload mirrors the
repository layout — but runtime files (like `mail-capture.php`) are packaged under
`payload/runtime/`, while installer files (the migration itself) are packaged under
`payload/lib/installer/`. Looking for the file in the wrong place raised a
`FileNotFoundError` and the update aborted.

This happened safely: `spawnwp update` runs migrations before activating a release, so
a host running 0.5.24 stayed on 0.5.24, fully functional, with nothing half-applied.

The migration now locates its source file correctly regardless of how the payload is
laid out, verified this time against an actual built release archive rather than the
repository checkout alone — the checkout's own directory shape had been masking the
bug in earlier testing.

Everything else in 0.5.25 is unchanged; see its [release notes](0.5.25.md) for the
actual fixes (the edge proxy timeout, WP-Cron, and Mailpit on every blueprint).
