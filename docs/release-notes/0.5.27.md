# SpawnWP 0.5.27

A second follow-up to 0.5.25. 0.5.26 fixed a failed update; this one fixes the
WP-Cron part of 0.5.25 itself, which turned out not to reach any site you already
had.

## Existing sites now actually get WP-Cron back

0.5.25 removed `DISABLE_WP_CRON` from the template new sites are built from, and
shipped a migration meant to clear it from sites you already had. That migration
didn't work, for two reasons that compounded:

`DISABLE_WP_CRON` is never written into `wp-config.php` as text. The WordPress image
re-evaluates the `WORDPRESS_CONFIG_EXTRA` environment variable on every request, so
the constant's value is whatever your site's container was given when it was last
created — clearing it with WP-CLI had nothing to find, because it was never there
to find.

And `spawnwp update` only ever rewrites the primary environment's own configuration.
Every other site you've created keeps the exact copy it was given at creation,
untouched by any later update — nothing was rewriting it to drop the old setting.

The migration now edits each site's own configuration directly — the line in
question has been identical since SpawnWP's very first release, so this is safe
everywhere — and recreates its PHP container so the fix actually takes effect. A
site you've deliberately stopped is left stopped; it picks up the fix the next time
you start it yourself, exactly as if it had been created fresh.

## Nothing else changes

The edge proxy timeout and Mailpit-on-every-blueprint fixes from 0.5.25 were correct
as shipped and are unchanged. If you're already on 0.5.26, this update only touches
the WP-Cron piece.
