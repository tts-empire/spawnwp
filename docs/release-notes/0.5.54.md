# 0.5.54 — Adminer 6.3.0 and verified image updates

New sites use a verified Adminer 6 image, with 6.3.0 as this release's baseline.
System → Prepare Adminer update follows the 6.x series and verifies both the Adminer
application version and its bundled PHP patch level. It prepares an image without
changing existing sites.

To update an existing site, prepare the image in System, then choose Update Adminer
on that site's Manage card. Updating SpawnWP alone does not replace its Adminer image.
The action briefly recreates only Adminer. WordPress, its PHP container and MariaDB
are not restarted. Stopped Adminer services remain stopped and use the selected image
when started later.

The update recognizes standard legacy Compose declarations that would otherwise ignore
the prepared image reference. It checks the image actually running, its PHP and HTTP
readiness before reporting success, and retains the previous exact image for rollback.
Custom Adminer images, ambiguous declarations and conflicting image overrides require
manual review. An update that cannot select the requested image is reported as an error.

Cockpit now shows the Adminer application version separately from PHP. The update action
is available even when PHP is already patched; a PHP success message alone is no longer
used as evidence that the Adminer application was upgraded.

This release covers a legacy configuration path relevant to issue #23. Confirmation on
the reporting user's installation is still required before considering that case resolved.
See the runtime migration guide for update and rollback instructions.
